# SQL-примеры

Четыре небольших запроса по таблицам CV Builder. **Они подготовлены после исходного прогона и не выполнялись.** Готовых результатов для них нет.

| Запрос | Что помогает проверить | Конструкции |
|---|---|---|
| [Список резюме](resumes.sql) | Найти документы по ID, сверить название и версию | SELECT, WHERE, ORDER BY |
| [Резюме и его навыки](resume-skills.sql) | Сопоставить сохранённые навыки с документом; увидеть резюме без навыков | LEFT JOIN с одной таблицей |
| [Количество навыков](skill-counts.sql) | Найти среди выбранных резюме документы с несколькими навыками | GROUP BY, COUNT, HAVING |
| [Навыки без повторов](unique-skills.sql) | Получить список разных названий навыков | DISTINCT |

Таблицы и колонки взяты из сохранённой схемы и ответов API: `resumes.id/title/revision`, `skills.resume_id/skill_name/level`. В файлах указаны ID исходных тестовых резюме. Для повторения можно подставить ID своих документов, сохранив фильтры WHERE. Все запросы только читают данные; использовать тестовый стенд `jerwfvhpoanoukxiyvwq` и разрешённый доступ. SQL-доступ владельца базы не заменяет проверку RLS с пользовательским JWT.

Пустой ответ не обязательно означает ошибку: документ может отсутствовать или быть недоступен текущему пользователю. В запросе с HAVING строки не возвращаются, если подходящих резюме с несколькими навыками нет.
