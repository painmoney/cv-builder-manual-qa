# Тест-план CV Builder

## Цель и объект

Оценить основные сценарии дипломного веб-приложения CV Builder, сохранность документов и разграничение доступа на отдельном QA-стенде.

## Scope / Out of Scope

В scope: Auth, CRUD/rename/copy, валидация email и возраста, пять шаблонов, предпросмотр, экспорт PDF/DOCX/Markdown, REST/RPC, revision, SQL, RLS, Storage и публичное резюме.

Вне scope: production, нагрузочное тестирование, полноценный аудит безопасности, кроссбраузерная матрица, реальные мобильные устройства, PNG/JPG-экспорт и все комбинации полей.

## Виды тестирования

Функциональное, негативное, интеграционное, проверка разграничения доступа, адаптивности и исследовательское тестирование. Это первоначальный прогон; регрессия и retest исправления не выполнялись. [Приёмы тест-дизайна](test-design.md).

## Инструменты

Управляемый Chromium-браузер; Node.js fetch / Supabase JS; SQL connector (SELECT); pypdf, python-docx и Poppler для анализа экспорта; Git/GitHub. Postman-коллекция — для последующего воспроизведения, без скриптов.

## Тестовые данные

Два синтетических пользователя A/B и по собственному документу. Для удаления — отдельная копия и временный документ, для Storage — одноразовая PNG. Подтверждение signup-токена проверялось на подготовленном аккаунте без отправки email. Пароли, ключи, JWT и данные входа хранятся вне репозитория; запросы доступа выполняются с пользовательской авторизацией. Перед воспроизведением подтвердить staging `jerwfvhpoanoukxiyvwq`.

## Основные риски

Доступ к чужим данным, потеря сохранения, перезапись устаревшей версией, повреждение экспорта. Внешние email/OAuth/GitHub/Puter и отсутствие управления offline ограничивают сценарии; подробности — в итоговом отчёте.
