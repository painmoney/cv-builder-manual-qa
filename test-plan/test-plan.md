# Тест-план CV Builder

## Цель

Проверить основные сценарии создания резюме, сохранность данных и разграничение доступа на отдельном QA-стенде дипломного приложения.

## Что входит в проверку

Авторизация и сессия; создание, редактирование, копирование, переименование и удаление резюме; валидация; пять шаблонов и экспорт; API/RPC, версии документов, SQL, RLS, файлы и публичное резюме.

Вне проверки: production, нагрузка, полноценный аудит безопасности, все комбинации полей, другие браузеры и реальные мобильные устройства, экспорт PNG/JPG.

## Виды тестирования

Функциональное, негативное, интеграционное, проверка доступа, адаптивности и исследовательское тестирование. [Примеры тест-дизайна](test-design.md).

## Инструменты и данные

Технический прогон: управляемый браузер, Node.js fetch / Supabase JS, SQL-подключение только для чтения; pypdf, python-docx и Poppler для проверки экспорта. Коллекция Postman подготовлена для самостоятельной отправки запросов, без скриптов.

Два синтетических пользователя A/B и их документы. Для удаления — отдельная копия и временное резюме; для файлов — одноразовая PNG. Подтверждение регистрации проверялось на подготовленном аккаунте без отправки письма. Пароли, ключи и токены хранятся вне репозитория. Запросы доступа выполняются с пользовательскими JWT; перед повторением проверить адрес staging.

## Риски

Доступ к чужим данным, потеря изменений, перезапись устаревшей версией, ошибки экспорта. Внешние сервисы и настройки могут блокировать часть сценариев; [причины пяти Blocked](../test-results/summary.md#что-не-удалось-проверить) перечислены в отчёте.

## Критерии начала и завершения

Начало: стенд доступен, версия и staging подтверждены, A/B и список проверок подготовлены.

Завершение: у всех 55 проверок текущего набора есть статус и фактический результат, доказательства сохранены, дефект оформлен. Временные документы и PNG удалены, основные документы A/B и аккаунты сохранены.
