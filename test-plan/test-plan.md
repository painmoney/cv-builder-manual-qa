# План тестирования CV Builder

## Объект и цель

Проверка собственного дипломного веб-приложения CV Builder на отдельном staging. Цель — оценить основные пользовательские сценарии, сохранение и изоляцию данных и подготовить воспроизводимые доказательства. Разработка приложения и выполнение этого прогона — отдельные факты.

## Scope

Auth password login/logout/session и token confirmation, CRUD/rename/copy, валидация email/возраста, пять шаблонов, предпросмотр, PDF/DOCX/Markdown, REST/RPC, revision conflict, SQL integrity и каскад, RLS и Storage, публичное согласованное резюме.

Out of scope: production, нагрузка, полноценный penetration test, кроссбраузерная матрица, реальные мобильные устройства, PNG/JPG export, исчерпывающие комбинации каждого поля. Email/OAuth/GitHub/Puter и реальный offline поток ограничены зависимостями. Успешное выполнение выбранных сценариев не является подтверждением отсутствия остальных дефектов.

## Модель и риски

[Модель из 55 исходных проверок и одной исследовательской](model.json). Высший риск: чужие данные, потеря сохранения, конфликт версий, повреждение экспорта. Основные состояния документа: отсутствует → создан revision 1 → сохранён revision n → конфликт либо новая revision → удалён. Предположения отделяются от SQL/исходников и пользовательских требований.

## Инструменты и способ выполнения

Браузерные locator/DOM/screenshot/viewport/console средства; Node.js fetch и Supabase JS для пользовательских HTTP-запросов; Supabase SQL connector только для SELECT; Git/GitHub; pypdf, python-docx и Poppler для экспорта. Postman collection предназначена для самостоятельного воспроизведения, Runner/test scripts отсутствуют. Browser Network panel и offline переключатель не были доступны; собственные HTTP-запросы клиента не выдаются за захват Network браузера.

Административная генерация signup-ссылок использовалась только для подготовки новых синтетических аккаунтов без отправки email. Все RLS/API/Storage проверки выполнялись с пользовательскими JWT или без авторизации; service-role не имитировал пользователя. Прямые SQL-записи и изменение схемы в этом прогоне не выполнялись.

## Критерии

Начало: READY QA deployment, подтверждённый staging ref, известная версия, синтетические A/B, модель проверок. Завершение: каждому пункту присвоен обоснованный статус, сохранены доказательства выполненных сценариев, оформлены отклонения/ограничения; временная копия, cascade-документ и avatar удалены. Основные A/B документы сохранены, аккаунты не удалялись.

## Риски и ограничения

Нет реального почтового ящика/SMTP-прогона, server GitHub token, OAuth конфигурации и Puter-сессии. Нет средства воспроизведения сетевого разрыва. DOCX проверен структурно и по тексту; LibreOffice/Word для визуального просмотра отсутствует. Browser viewport не доказывает поведение на устройстве. Точные ограничения навыков и результаты отражены в [отчёте](../test-results/summary.md).
