# TC-12 SQL integrity, cascade и Storage ownership

Приоритет: High.

## Предусловия

A/B и отдельный disposable UUID. Только staging ref подтверждён.

## Тестовые данные

Синтетический payload с четырьмя дочерними разделами; одноразовая PNG. Пароли и JWT в публичный документ не включаются.

## Шаги

1. SELECT каталог PK/FK/RLS/RPC.
2. SELECT LEFT JOIN/GROUP BY для известных синтетических ID.
3. Создать disposable через пользовательский RPC, прочитать связи.
4. DELETE владельцем, SELECT дочерних таблиц.
5. Загрузить PNG в prefix A; B пытается upload/delete в A.
6. Проверить public GET после попытки B, удалить файл владельцем.

## Ожидаемый результат

Связи и поля соответствуют; после удаления 0 зависимых строк; чужой Storage write запрещён, public read разрешён контрактом.

## Постусловия

Disposable и PNG удалены; основные A/B документы остаются.
