# TC-16 — Каскадное удаление резюме

**Приоритет:** High. **Проверки:** DB-03.

## Предусловия

Только staging; пользователь A и SQL-доступ только для чтения. Для проверки удаления создать отдельный временный документ.

## Тестовые данные

Временное резюме с навыком, образованием, опытом и проектом. Использовать новый UUID; основные документы A/B не удалять.

## Шаги и ожидаемые результаты

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Создать временный документ через пользовательский RPC create_resume_full и прочитать его со связанными записями через API. | Есть резюме и записи в skills, education, experience, manual_projects. |
| 2 | Отправить DELETE временного документа от владельца. | Документ удалён. |
| 3 | Подставить ID удалённого документа в `SELECT COUNT(*) FROM public.resumes WHERE id = '<UUID>';` и `SELECT COUNT(*) FROM public.skills WHERE resume_id = '<UUID>';`. Второй запрос повторить для education, experience и manual_projects. | Все пять запросов возвращают 0. |
| 4 | От владельца прочитать удалённый документ и его связи через API: `GET /rest/v1/resumes?id=eq.<UUID>&select=id`; для каждой из четырёх дочерних таблиц — `GET /rest/v1/<таблица>?resume_id=eq.<UUID>&select=id`. | Каждый ответ — HTTP 200 с пустым массивом. |

## Постусловия

Ожидаемое состояние после выполнения: временное резюме и зависимости удалены, основные A/B сохранены. Результат DB-03 не представлен в сводке. Этот кейс описывает подготовленный сценарий проверки удаления.
