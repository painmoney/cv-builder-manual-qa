# TC-11 — Изоляция документов двух пользователей

**Приоритет:** Critical. **Проверки:** API-09, API-10, SEC-01, SEC-02, SEC-03, SEC-04, SEC-05.

## Предусловия

A и B имеют по собственному документу. В HTTP-клиенте можно переключать пользовательскую авторизацию.

## Тестовые данные

ID документов A/B; отдельные пользовательские сессии; тело запроса к skills с колонкой skill_name.

## Шаги и ожидаемые результаты

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Под A выполнить GET документа B; повторить B → A. | Оба ответа HTTP 200 с `[]`. |
| 2 | В обоих направлениях вызвать RPC сохранения чужого документа. | HTTP 400, код P1004. |
| 3 | В обоих направлениях выполнить чужие PATCH и DELETE. | HTTP 200 с `[]`. |
| 4 | Прочитать документы их владельцами. | Оба существуют; title/revision/data не изменены чужими запросами. |
| 5 | Попытаться вставить skills в чужое резюме. | HTTP 403, RLS отклоняет вставку. |
| 6 | Поочерёдно войти A/B в браузере и открыть чужой редактор. | Редактирование чужого документа недоступно. |
| 7 | Отправить запрос создания без пользовательского JWT. | HTTP 401, код 42501. |
| 8 | Отправить GET с невалидным JWT. | HTTP 401, код PGRST301; данные не раскрыты. |

## Постусловия

Документы владельцев сохранены; браузерные сессии завершены.
